# Готовность 7TOOL к Яндекс Директу и динамическому ремаркетингу

Счётчик: `109097461`. Кампании и расход бюджета этим проектом не запускаются.

## Цели Метрики

Создать JavaScript-цели с идентификаторами, в точности совпадающими с названиями ниже.

| Уровень | Идентификаторы |
|---|---|
| Диагностика | `lp_view`, `view_category`, `view_product`, `search`, `lp_quick_choice`, `lp_selector_start`, `lp_selector_complete`, `lp_form_start`, `lp_product_click` |
| Микроконверсии | `add_to_cart`, `begin_checkout`, `click_phone`, `click_email`, `click_messenger`, `download_catalog`, `download_kp` |
| Основные онлайн-лиды | `lp_lead_submit`, `submit_product_quote`, `submit_one_click`, `submit_equipment_selection`, `submit_contact`, `submit_cart_quote`, `submit_price_match` |
| Офлайн-результаты | `qualified_call`, `lead_qualified`, `lead_won` |

`submit_order` и Ecommerce `purchase` сейчас не создаются: сайт формирует запрос КП, а не оплаченный заказ. `click_phone` — только микроконверсия. Для автостратегии Директа использовать подтверждённые онлайн-лиды, а после накопления данных — `lead_qualified` или `lead_won`.

Одна сохранённая заявка создаёт одну основную онлайн-цель. Событие отправляется только после успешного ответа API. Параметры проходят allowlist; телефон, email, ФИО, ИНН, компания, сообщение и файлы в Метрику не передаются.

Карта форм и единственной основной цели:

| Форма | API/БД | Цель после подтверждения записи |
|---|---|---|
| Рекламный лендинг | `landing_quote` | `lp_lead_submit` |
| КП по товару | `product_quote` | `submit_product_quote` |
| Купить в 1 клик | `one_click` | `submit_one_click` |
| Подбор категории/товара | `equipment_selection` | `submit_equipment_selection` |
| Контакты | `contact_form` | `submit_contact` |
| КП из корзины | `cart_quote` | `submit_cart_quote` |
| Нашли дешевле | `price_match` | `submit_price_match` |

Повтор одного `submissionId` возвращает исходный `requestId` и не отправляет вторую цель.

## Ecommerce и единый ID

Канонический рекламный объект — конкретный вариант товара. Схема ID:

```text
variant.id = A12345
YML offer id = k2-A12345
Ecommerce products.id = k2-A12345
URL = https://7tool.ru/p/<slug>?variant=A12345
заявка/корзина = variant_id A12345
```

SKU используется только как `vendorCode`/`variant`, но никогда как ключ. Это защищает ремаркетинг от пустых и повторяющихся артикулов.

Контрольные связки из актуального каталога:

| URL | `product.id` | `variant.id` | SKU | `offer id` / `products.id` |
|---|---|---|---|---|
| `/p/borfrezy-tverdosplavnye-lenz-forma-c-tsilindr-so-sfericheskim-kontsom?variant=A4705` | `G4101` | `A4705` | `LZBC 055 N3` | `k2-A4705` |
| `/p/magnitnyy-sverlilnyy-stanok-lenz-steyr-35?variant=A9409` | `A9409` | `A9409` | `STEYR-35` | `k2-A9409` |
| `/p/magnitnyy-sverlilnyy-stanok-ms-36?variant=A8798` | `A8798` | `A8798` | пустой | `k2-A8798` |
| `/p/kromkorez-ruchnoy-ravic-rv-7?variant=A27735` | `A27735` | `A27735` | `401.0002` | `k2-A27735` |
| `/p/truborez-elektricheskiy-ravic-rv-706-dlya-trub-16-60-mm-201-0005?variant=A27120` | `A27120` | `A27120` | `201.0005` | `k2-A27120` |

События Ecommerce:

- `impressions` — видимая карточка каталога;
- `click` — переход из каталога или рекламного лендинга;
- `detail` — фактически выбранный вариант на странице товара;
- `add` — добавление конкретного варианта в корзину;
- `remove` — уменьшение или удаление из корзины;
- `begin_checkout` — начало заполнения формы КП;
- `purchase` — зарезервировано до появления реального заказа.

## Рекламный YML

Постоянный URL после production-выкладки:

```text
https://7tool.ru/feeds/yandex-dynamic.xml
```

Файл отдельный от дилерского импорта. Он генерируется атомарно после успешной проверки каталога. При ошибке старая версия остаётся на месте, а причина записывается в `.analysis/yandex-advertising-feed.json.errors.log`.

Фильтр исключает draft/непубличные/незаказываемые позиции, конфликт `G1031`, варианты без цены или изображения и повторные offer ID. Повторяющийся SKU не используется как ключ и не удаляет валидный offer: такие случаи отдельно перечисляются в `duplicateSkus` отчёта `.analysis/yandex-advertising-feed.json` для проверки поставщиком.

Подключение в Директе:

1. Сначала проверить URL, HTTP 200, `Content-Type` XML, дату генерации и отчёт конфликтов.
2. В Директе создать фид для динамических объявлений из URL выше.
3. Дождаться результата проверки фида и устранить отклонённые предложения.
4. Проверить на трёх товарах точное совпадение `offer id` с `products.id` в Ecommerce.
5. Только затем создавать группы объявлений. Запуск, ставки и бюджет выполняются владельцем отдельно.

## Сегменты ремаркетинга

Создавать в Метрике после подтверждения поступления событий:

| Сегмент | Условие | Окно | Исключение |
|---|---|---:|---|
| Товар без заявки | `view_product`, нет ни одной основной цели | 1–7 дней | квалифицированные и сделки |
| Категория | `view_category`, нет основной цели | 8–30 дней | лиды |
| Корзина без отправки | `add_to_cart`, нет `submit_cart_quote` | 1–14 дней | лиды |
| Начал форму | `lp_form_start`/`begin_checkout`, нет основной цели | 1–14 дней | лиды |
| Дорогое оборудование | `view_product` + категория оборудования | до 90 дней | лиды и сотрудники |
| Повтор расходников | покупатели/квалифицированные лиды категории расходников | согласовать цикл | спам, тесты, возвраты |

Для конкретного товара использовать Ecommerce-аудиторию по `products.id`; показывать тот же offer или доступные аналоги. В отчётах исключать внутренний трафик, тестовые визиты, spam/duplicate/lost и снятые предложения.

## Проверка в авторизованной Метрике

До запуска рекламы выполнить:

1. Открыть сайт с тестовыми `utm_*` и `yclid`.
2. В консоли браузера подтвердить наличие `window.ym`, счётчика `109097461` и массива `dataLayer`.
3. В режиме отладки проверить `view_category`, `view_product`, `detail`, `add`, `remove`, `begin_checkout`.
4. Отправить по одной контролируемой форме каждого типа и сверить: одна запись БД, один `request_id`, одна основная цель.
5. В админке проверить `yclid`, настоящий числовой ClientID, first-touch и last non-direct.
6. В интерфейсе Метрики подтвердить визит и цели. Не считать локальный лог доказательством поступления данных в Метрику.
7. Для тестовой офлайн-выгрузки дождаться статуса `PROCESSED`; HTTP 200 и `accepted` ещё не доказывают обработку данных.

Webvisor оставлен выключенным. Его можно включить только после отдельной проверки маскирования всех полей с персональными данными.
