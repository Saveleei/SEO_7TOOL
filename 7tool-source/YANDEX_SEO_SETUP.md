# Настройка Яндекс Вебмастера для 7TOOL.ru

Дата: 18 августа 2026 года. Действия в аккаунте владельца не выполнялись: для них требуется его авторизованная сессия. Техническая часть сайта подготовлена.

## Что уже готово на сайте

- Основное зеркало и canonical: `https://7tool.ru`.
- `https://7tool.ru/robots.txt` отвечает 200, содержит `Host`, `Sitemap`, закрывает `/admin` и `/api`.
- Tracking-параметры очищаются директивой `Clean-param`; фильтры получают `noindex, follow` и canonical на базовую категорию.
- `https://7tool.ru/sitemap.xml` отвечает 200 и содержит только проверенные self-canonical URL.
- Cart, favorites, фильтры и рекламные LP исключены из индексации.
- Товарные, категорийные и брендовые страницы имеют canonical, H1, metadata и JSON-LD.

## Подключение

1. Войти в [Яндекс Вебмастер](https://webmaster.yandex.ru/), добавить точно `https://7tool.ru`.
2. Подтвердить права. Для этого проекта предпочтителен HTML-файл в корне или DNS TXT. Meta tag тоже допустим, но его токен нельзя придумывать заранее.
3. Не удалять проверочный файл/запись после подтверждения: Яндекс периодически перепроверяет права.
4. В разделе индексирования добавить `https://7tool.ru/sitemap.xml`.
5. Проверить главное зеркало, статус robots и последние ошибки sitemap.

Официальные инструкции: [подтверждение прав](https://yandex.ru/support/webmaster/en/service/rights), [Sitemap](https://yandex.ru/support/webmaster/en/indexing-options/sitemap), [Clean-param](https://yandex.ru/support/webmaster/en/robot-workings/clean-param), [canonical](https://yandex.ru/support/webmaster/en/robot-workings/canonical?lang=en).

## Первые URL для переобхода

Отправлять партиями после подключения, без массовой отправки всех товаров:

1. `https://7tool.ru/`
2. Четыре новые категории: `/c/sverla-i-zenkovki`, `/c/stanki-lazernoy-rezki`, `/c/svarochnye-roboty`, `/c/stanochnaya-osnastka`.
3. Основные категории с обновлённой пагинацией.
4. Несколько контрольных товарных и брендовых URL из sitemap.

## Контроль через 3–14 дней

- Диагностика: критические и фатальные ошибки.
- Статистика обхода: всплески 5xx, долгий ответ, аномальный объём фильтров.
- Страницы в поиске: рост indexable category/product URLs, отсутствие `/cart`, `/favorites`, query filters и `/lp/`.
- Исключённые страницы: canonical/noindex должны объяснять исключение; 404 из sitemap быть не должно.
- Поисковые запросы: показы/клики по новым категориям, не только позиции.
- Внешние/внутренние ссылки: приоритетные категории должны получать ссылки с главной и тематических материалов.
- Качество сайта: контролировать коммерческие и технические сигналы, не реагировать на единичные колебания.

## Валидация разметки

Проверить главную, категорию, brand page и 3–5 товаров в [валидаторе микроразметки Яндекса](https://webmaster.yandex.ru/tools/microtest/). Официальное описание: [Schema.org в Яндексе](https://yandex.ru/support/webmaster/en/schema-org/intro-schema-org) и [валидатор](https://yandex.ru/support/webmaster/en/yandex-indexing/validator).

## Что не делать

- Не закрывать в `robots.txt` URL, на которых робот должен увидеть `noindex` или canonical.
- Не добавлять параметры фильтров и рекламные LP в sitemap.
- Не менять массово canonical на основании единичных отчётов.
- Не отправлять на переобход конфликтный товар G1031 до исправления исходных характеристик.
- Не использовать автоматически сгенерированный SEO-текст без проверки специалистом по продукту.

## Еженедельный регламент

1. Проверить диагностику, sitemap и ответы сервера.
2. Сравнить индексируемые URL с `seo:check` и фактическим sitemap.
3. Разобрать запросы с показами и низким CTR: сначала релевантность и сниппет, затем текст.
4. Перед созданием новой посадочной заполнить decision card: intent, спрос, ассортимент, конкурирующий URL, решение `CREATE/KEEP/MERGE/NOINDEX/CANONICALIZE/REJECT`.
5. Зафиксировать изменения и дату; не менять URL без redirect map.
