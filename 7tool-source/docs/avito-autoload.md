# Avito Autoload для 7TOOL

Модуль формирует кандидата Avito XML из дилерского фида, но не отправляет его в Avito. Рабочий файл заменяется только явной командой `--publish-local`; подключение URL в кабинете остаётся отдельным ручным действием владельца.

## Что реализовано

- импорт supplier XML из локального файла или HTTPS URL;
- нормализация SKU, цен, остатков, параметров и изображений;
- стабильный ID объявления из supplier offer ID;
- объяснимый коммерческий скоринг и лимит 100–300 SKU;
- ручные include/exclude/pin списки;
- квоты категорий и лимит SKU на одну товарную линейку;
- детерминированные русские заголовки и описания без генерации новых фактов;
- проверка новых чисел и рекламных суперлативов в AI-черновиках;
- Avito XML v3 в UTF-8 с корректным экранированием;
- реальные складские кадры как отдельные элементы в конце галереи;
- HTML-предпросмотр, JSON-отчёт и причины исключения;
- защита от резкого сокращения фида;
- один grace-цикл для единично пропавшей позиции;
- атомарная запись и последняя корректная версия;
- CSV-аналитика по показам, контактам, КП, заказам и прибыли;
- локальная оценка и консервативное улучшение изображений через Sharp;
- создание честного складского слайда с подписью поверх реальной фотографии;
- подключаемый AI image enhancer, результат которого всегда требует ручного подтверждения.

## Почему схема Avito не зашита в код

Обязательные поля и допустимые значения зависят от ветки категории и меняются со временем. Значения `Category`, `GoodsType`, `AdType`, `Condition` и дополнительные поля нужно перенести из шаблона автозагрузки, доступного для категории в кабинете Avito.

В `config/avito.example.json` значения `GoodsType` намеренно оставлены плейсхолдерами, а `schemaVerified` имеет значение `false`. Такой товар будет исключён. Это защищает от публикации фида с угаданным справочником.

Файл `fixtures/avito/config.test.json` предназначен только для синтаксического теста. Его `GoodsType` не является подтверждённым справочным значением Avito.

## Быстрая проверка

```bash
npm run avito:fixture
npm run avito:test
```

Результаты фикстуры:

- `fixtures/avito/generated/candidate-avito.xml` — тестовый XML;
- `fixtures/avito/generated/report.json` — выбранные и исключённые SKU;
- `fixtures/avito/generated/preview.html` — фильтруемый предпросмотр;
- `fixtures/avito/generated/candidate-state.json` — кандидат состояния, не рабочий state.

## Подключение реального фида

1. Скопировать `config/avito.example.json` в `config/avito.local.json`.
2. Оставить `source.trustConfiguredFeedHost: true`, если используется существующий production-секрет K2Tool `FEED_URL`. Для явного URL вне secret store внести hostname в `source.allowedHosts`.
3. По умолчанию конвейер повторно использует `FEED_URL/FEED_FILE` сайта. `AVITO_FEED_URL/AVITO_FEED_FILE` нужны только для отдельного источника.
4. Перенести поля из актуального шаблона Avito для каждой категории.
5. После проверки поставить `schemaVerified: true` только для фактически проверенной ветки.
6. Заполнить себестоимость либо допустимую маржу для приоритетных SKU.
7. Выполнить dry-run.

```bash
AVITO_CONFIG=config/avito.local.json \
FEED_FILE=../dealer-2.xml \
npm run avito:dry-run
```

На Windows переменные можно задать в `.env.local` или в окружении процесса. CLI не читает `.env.local` самостоятельно: production runner должен передать их в runtime environment так же, как для существующего supplier feed.

## Ручная локальная публикация файла

После проверки `report.json`, `preview.html` и тестовой загрузки в валидаторе:

```bash
npm run avito:publish-local
```

Команда атомарно создаёт `public/feeds/avito.xml` и обновляет `.avito/last-good-state.json`. Это всё ещё не подключает фид к Avito. Публичный URL появится только после деплоя сайта и ручного добавления адреса в кабинете.

Не запускайте `publish-local`, если в конфигурации остались тестовые значения.

## Скоринг

Используется произведение факторов:

```text
demand × stock × margin × priceCompetitiveness
× contentQuality × upsellPotential × shippingSpeed
```

Если спрос, конкурентная цена или себестоимость неизвестны, применяется нейтральный коэффициент и в отчёт добавляется предупреждение. Система не имитирует наличие рыночной аналитики.

Жёсткие причины исключения:

- категория не сопоставлена;
- схема категории не подтверждена;
- нет положительной цены;
- недостаточно изображений;
- нет подтверждённого остатка;
- подтверждено отсутствие;
- ручной запрет;
- маржа ниже заданной.

После жёстких проверок применяются `selection.categoryLimits` и `selection.maxPerFamily`. Стартовые квоты откалиброваны на актуальном фиде K2Tool для пилота до 200 объявлений: это не позволяет тысячам типоразмеров одной серии вытеснить оборудование и другие категории. Ручные `includeSkus` и `pinnedSkus` обходят квоты, но не обходят обязательную цену, изображения и подтверждённую схему Avito.

## Остатки и аварийная защита

- Полностью недоступный или слишком маленький supplier feed не заменяет рабочую версию.
- Резкое сокращение относительно предыдущего запуска блокируется `maxSourceDropRatio`.
- Единично пропавший SKU может сохраняться один цикл со статусом `grace`; описание при этом требует повторного подтверждения наличия.
- Подтверждённый `available=false` исключается сразу.
- `missingProductGraceRuns` и `allowGraceListings` настраиваются.

Для дорогого оборудования рекомендуется `missingProductGraceRuns: 0`, если поставщик передаёт надёжные построчные статусы.

## Изображения

Проверка локального файла:

```bash
node scripts/avito-images.mjs inspect public/warehouse/01.webp
```

Консервативная производная без увеличения разрешения:

```bash
node scripts/avito-images.mjs enhance public/warehouse/01.webp --output .avito/images
```

Складской слайд из реальной фотографии:

```bash
node scripts/avito-images.mjs warehouse public/warehouse/01.webp --output public/avito/warehouse-proof.webp
```

Карточка характеристик создаётся только из проверенного JSON, например `product-card.json`:

```json
{
  "title": "Магнитный сверлильный станок LENZ STEYR-35",
  "sku": "STEYR-35",
  "price": 47999,
  "params": [{ "name": "Шпиндель", "value": "Weldon 19" }]
}
```

```bash
node scripts/avito-images.mjs spec product-card.json --output public/avito/steir-35-spec.webp
```

После публикации производной её HTTPS URL можно добавить в `images.generatedBySku`. Система расположит карточку после предметных фотографий и до складского кадра.

Локальная обработка выполняет autorotate, нормализацию, умеренную резкость и WebP-кодирование. Исходник не изменяется. Увеличение разрешения и любой AI-результат должны иметь статус ручной проверки.

Запрещено использовать AI для дорисовки деталей, комплектации, маркировки или помещения конкретного товара на склад. AI adapter в `src/lib/avito/image-pipeline.mjs` не подключён к внешнему провайдеру и по умолчанию выключен.

Удалённые изображения разрешены только по HTTPS с hostname из allowlist. Локальные и служебные IP блокируются.

## Контент

Детерминированный шаблон использует только:

- название, бренд и SKU;
- фактическую цену;
- подтверждённый статус;
- параметры фида;
- комплектацию фида;
- подтверждённые условия компании из конфигурации;
- отраслевой use case и вопросы из проверенной категории.

AI-текст можно подключить поверх структурированных данных, но до публикации необходимо:

1. получить структурированный результат;
2. проверить сохранность бренда, артикула и всех чисел;
3. отклонить новые факты;
4. провести ручную проверку первых партий.

## Аналитика

Поддерживается CSV с колонками:

```text
ad_id,sku,category,city,impressions,views,contacts,qualified_leads,
proposals,orders,revenue,gross_profit,placement_cost,promotion_cost,loss_reason
```

Пример:

```bash
node scripts/avito-pipeline.mjs \
  --feed fixtures/avito/supplier.xml \
  --config fixtures/avito/config.test.json \
  --analytics fixtures/avito/analytics.csv \
  --output fixtures/avito/generated \
  --dry-run
```

Модуль считает конверсию в контакт, долю квалифицированных лидов, конверсию КП в заказ, стоимость контакта, стоимость квалифицированного лида, прибыль после Avito и ROI.

## Что требуется от владельца 7TOOL

Перед рабочим запуском нужны:

1. Доступ к production-секрету `FEED_URL` K2Tool либо локальная копия supplier feed.
2. Актуальный шаблон автозагрузки Avito для выбранной категории.
3. Подтверждённые значения `GoodsType`, `AdType`, `Condition` и дополнительных полей.
4. Условия тарифа, лимит объявлений и правила снятия позиций.
5. Себестоимость или минимальная допустимая маржа хотя бы для стартовых SKU.
6. Подтверждение телефона, адреса, гарантии и условий постоплаты.
7. Подтверждение прав на изображения поставщика и склада.
8. Решение, допустимо ли добавлять складской слайд в выбранной категории.
9. Экспорт статистики Avito и связка с заказами/валовой прибылью.

## Риски перед подключением аккаунта

- неподтверждённый справочник категории приведёт к отклонению объявлений;
- устаревший остаток может создать ложное обещание наличия;
- групповые товары необходимо согласовать: одно объявление на модель или отдельное на SKU;
- фотографии поставщика могут иметь ограничения по лицензии или водяные знаки;
- складской кадр нельзя выдавать за фотографию конкретного товара;
- массовое региональное дублирование не реализовано и не должно добавляться без официально доступного механизма;
- dry-run и локальные тесты не заменяют тестовую загрузку и отчёт модерации Avito.

## Структура

- `src/lib/avito/core.mjs` — нормализация, скоринг, контент, XML и preview;
- `src/lib/avito/image-pipeline.mjs` — безопасность и обработка изображений;
- `src/lib/avito/analytics.mjs` — импорт CSV и экономика объявлений;
- `scripts/avito-pipeline.mjs` — безопасный CLI;
- `scripts/avito-images.mjs` — локальные операции с изображениями;
- `config/avito.example.json` — production-safe пример;
- `fixtures/avito` — полностью локальная тестовая выборка;
- `tests/avito-pipeline.test.mjs` — автоматические проверки.
