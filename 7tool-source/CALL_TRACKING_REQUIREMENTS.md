# Данные для подключения динамического коллтрекинга

Провайдер пока не выбран, поэтому выдуманная интеграция не подключается. На сайте подготовлен нейтральный webhook:

```text
POST https://7tool.ru/api/integrations/call-tracking
Authorization: Bearer <CALL_TRACKING_WEBHOOK_SECRET>
Content-Type: application/json
```

## Что нужно получить от владельца и провайдера

- название сервиса и доступ к кабинету;
- документацию webhook/API;
- секрет подписи или токен webhook;
- пул подменных номеров и правила географии;
- срок хранения данных и договор обработки персональных данных;
- правило уникальности звонка;
- правило квалификации и минимальной длительности;
- список статусов результата разговора;
- возможность передавать/возвращать `yclid`, ClientID Метрики и `request_id`;
- тестовый номер и тестовое событие без тарификации рекламы.

## Неперсональный контракт webhook

```json
{
  "provider_call_id": "unique-call-id",
  "request_id": "7T-20260818-ABC123",
  "client_id": "1234567890123456789",
  "yclid": "...",
  "source": "yandex",
  "campaign": "campaign-id",
  "answered": true,
  "is_unique": true,
  "duration_seconds": 96,
  "qualified": true,
  "result": "qualified",
  "started_at": 1787011200
}
```

Телефон клиента, имя и запись разговора в этот endpoint не нужны. `click_phone` остаётся микроконверсией. `qualified_call` ставится в очередь офлайн-конверсий только для реально квалифицированного события, связанного с существующим `request_id`.
