## 2. Обнаруженные эксплуатационные риски

1. `NEXT_PUBLIC_YANDEX_METRIKA_ID` отсутствует в production env и PM2. Счётчик не загружается, поэтому достоверную исходную воронку и поведение рекламного трафика из Метрики получить невозможно.
2. Почасовой и ночной cron вызывают shell-скрипты без права исполнения. В логах есть `Permission denied`; автоматическое обновление нужно восстановить перед production-релизом.
3. Таблица лидов до пилота не имела отдельных полей для `yclid`, ClientID, UTM, посадочной, статуса и выручки. Офлайн-конверсии нельзя было связать с рекламой без ручного разбора JSON.
4. `/catalog` отдавал 404.
5. В production-логах есть исторические ошибки Next.js `NoFallbackError` и превышения cache item size. Текущие публичные страницы из проверенной выборки отвечали 200, но логи нужно продолжить контролировать после релиза.

## 3. Реализованный пилот

Пять категорий, по два сценария:

| Категория | Сценарии |
|---|---|
| Борфрезы | по материалу, по форме |
| Сверлильные станки | магнитные, безщёточные |
| Корончатые свёрла | HSS, TCT |
| Кромкорезы по листу | мобильные, автоматические |
| Кромкорезы для труб | по диаметру, для монтажа |

Короткий URL `/lp/{category}` открывает основной сценарий. Неизвестные сценарии, неактивные категории и страницы с недостаточным контентом/ассортиментом дают 404. В каждой активной странице есть отдельная компактная шапка, оффер, три преимущества, форма с 2–3 вопросами, выбор канала, 12 реальных товаров, доверительные блоки, FAQ, нижняя форма и мобильная CTA-панель.

SEO-защита: `noindex, follow`, canonical на `/c/{category}`, отсутствие `/lp/` в sitemap.

## 4. Воронка и данные

События: `lp_view`, `lp_selector_start`, `lp_selector_complete`, `lp_form_start`, `lp_lead_submit`, `lp_product_click`, `lp_email_intent`, `quote_request`. Ecommerce передаётся через `dataLayer`.

Заявка сначала получает внешний номер и сохраняется в SQLite, затем выполняется SMTP. Сохраняются UTM, `yclid`, собственный ClientID, ClientID Метрики, посадочная, категория, сценарий, ответы, статус и сумма. Email-кнопка сначала фиксирует намерение на сервере, затем открывает `mailto:`.

Файл спецификации: до 10 МБ, PDF/Excel/CSV/Word, проверка расширения, MIME и сигнатуры, случайное имя, режим файла 0600, непубличный карантин, опциональный ClamAV.

## 5. Контроль качества

- ESLint: без ошибок.
- Автоматические тесты: 15/15.
- Production build Next.js: успешно.
- Все 10 сценариев и 5 fallback-URL: 200, `noindex`, 12 товаров.
- Неизвестный сценарий и неактивная категория: 404.
- Проверка формы в браузере: успешная запись, номер обращения, атрибуция и ClientID в отдельных полях.
- Защита Origin: чужой Origin — 403 `BAD_ORIGIN`; заявка без телефона/email — 400.
- Время ответа локального production-режима: первый запрос около 404 мс, повторные 51–334 мс.
- First Load JS landing: около 115 КБ по отчёту сборки.

Сборка нескольких старых статических категорий иногда превышает 60 секунд на первую попытку, после автоматического retry завершается успешно. Это не вызвано динамическими `/lp/`, но остаётся задачей производительности сборочного контура.

## 6. Backlog экспериментов

| Приоритет | Гипотеза | Метрика | Критерий решения |
|---|---|---|---|
| P0 | Контекстный H1 и 3 вопроса повышают квалифицированные обращения | `qualified / lp_view` | не менее +20% к обычной категории при сопоставимом трафике |
| P0 | Email как равноправный канал снижает потери B2B-аудитории | `lp_email_intent`, завершённые лиды | сохранить, если даёт ≥10% квалифицированных лидов без роста спама |
| P1 | 8 товаров вместо 12 ускоряют просмотр без потери конверсии | LCP, `lp_product_click`, `lp_lead_submit` | выбрать вариант с лучшим qualified rate при LCP ≤2,5 с |
| P1 | CTA «Получить цены, остатки и сроки» эффективнее «Получить КП» | start/submit form | победитель при ≥95% статистической уверенности и без падения качества |
| P2 | Сценарийная страница эффективнее широкого fallback | qualified rate | отключить узкий сценарий, если за достаточный период он хуже fallback >15% |

До подключения Метрики эксперименты запускать нельзя: сначала установить счётчик, цели, consent и проверить параметры в отладке.

## 7. Выкладка

Сейчас работает локальный стенд на `http://127.0.0.1:3111`. Для production требуется отдельное подтверждение владельца после просмотра. Порядок: backup SQLite и релиза → заполнение Метрики/закрытого хранилища/ClamAV → исправление cron → отдельный порт → smoke форм и SMTP → атомарное переключение symlink → мониторинг PM2, HTTP, cron и лидов → готовый откат на предыдущий release.
