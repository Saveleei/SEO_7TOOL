# Контекстные посадочные 7TOOL

## Что реализовано

Маршрут `/lp/{категория}/{сценарий}` формируется из конфигурации `src/lib/landing-pages.ts` и актуальной SQLite. Пилот охватывает борфрезы, сверлильные станки, корончатые свёрла, кромкорезы по листу и кромкорезы для труб.

Если конфигурация не проходит контентные проверки или в категории меньше шести корректных товаров, маршрут отвечает 404. Все landing page имеют `noindex, follow` и canonical на обычную категорию. Цена и наличие читаются при запросе, поэтому почасовой фид не требует пересборки именно для этих полей.

## Формы и данные

Заявка сначала записывается в таблицу `leads`, получает номер вида `7T-YYYYMMDD-XXXXXX`, затем отправляется SMTP. Отдельно сохраняются категория, сценарий, URL, UTM, `yclid`, собственный ClientID и ClientID Метрики, статус, сумма сделки и ответы на вопросы.

Спецификации принимаются только в PDF, XLS/XLSX, CSV, DOC/DOCX до 10 МБ. Проверяются расширение, MIME и сигнатура. Файлы лежат вне публичного `/uploads`. При `CLAMAV_ENABLED=1` чистый файл перемещается из карантина в закрытое хранилище, заражённый удаляется; при недоступном сканере файл остаётся в карантине.

Статус и сумму сделки менеджер меняет в `/admin/leads`. Квалифицированные и выигранные заявки с рекламным идентификатором выгружаются через кнопку «Выгрузить конверсии».

## Яндекс Метрика

На сервере необходимо задать `NEXT_PUBLIC_YANDEX_METRIKA_ID=109097461` до `npm run build`. В коде есть безопасный fallback на тот же счётчик, чтобы пропуск build-time env не отключал аналитику. События: `lp_view`, `lp_selector_start`, `lp_selector_complete`, `lp_form_start`, `lp_lead_submit`, `lp_product_click`, `lp_quick_choice`, `lp_email_intent`. Одна заявка лендинга создаёт только одну основную цель `lp_lead_submit`.

Подключён ecommerce-контейнер `dataLayer`. Перед запуском рекламы цели нужно создать в интерфейсе Метрики с точными именами выше и проверить в режиме отладки.

## Предрелизная проверка

1. Сделать SQLite backup и архив текущего релиза.
2. Заполнить `NEXT_PUBLIC_YANDEX_METRIKA_ID=109097461` и `PRIVATE_UPLOAD_DIR`.
3. Проверить `npm run lint`, `npm test`, `npm run build`.
4. Запустить релиз на отдельном порту и проверить пять категорий на desktop и 360 px.
5. Отправить тестовые заявки по телефону и email, с файлом и без него; убедиться, что номер появляется в `/admin/leads` до SMTP.
6. Проверить robots, canonical и отсутствие LP в sitemap.
7. Только после отдельного подтверждения переключать production symlink.

## Выявленные блокеры production

На аудите 11 августа 2026 года в production не был задан ID Метрики, поэтому достоверной базовой статистики по этим целям нет. Также текущие cron-записи вызывают `hourly-refresh.sh` и `nightly-rebuild.sh` напрямую, а файлы на сервере не имеют права исполнения. В логах это даёт `Permission denied`. Перед выкладкой следует либо поставить `chmod 755` обоим скриптам, либо вызывать их через `/bin/sh`, сохранив исходное расписание и сделав резервную копию crontab.

Production в рамках разработки посадочных не изменяется.
