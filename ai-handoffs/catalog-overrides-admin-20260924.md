## Цель

Добавить безопасный административный цикл ручного обогащения характеристик каталога поверх фида: черновик, серверная валидация, явная публикация, откат и журнал изменений. Исходные данные поставщика не переписывать.

## Ограничения

- Не менять исходный фид и не придумывать характеристики.
- Не публиковать невалидный или пустой набор параметров.
- Не давать публичному клиенту доступ к административным операциям.
- Не менять production, DNS, credentials и внешние каналы.
- Не отправлять формы и тестовые лиды.

## Критерий готовности

- Корректировки хранятся отдельно от фида и имеют состояния draft/published.
- Значения проходят серверную валидацию и привязаны к реальному товару.
- Публикация и откат выполняются только явным административным действием.
- Каждое изменение отражается в неизменяемом журнале аудита.
- Администратор может начать исправление из очереди качества и видеть результат проверки.
- Пройдены узкие тесты, полный test, lint, build и пропорциональная browser-проверка.

## Статус

Реализация и проверки завершены; код зафиксирован.

## Что реализовано

- Отдельное атомарное JSON-хранилище `catalog-parameter-overrides.json`; исходный `products.json` не изменяется.
- Полный контролируемый цикл:
  - сохранение черновика;
  - серверная проверка товара, исполнения, области, названия, значения и публичной ссылки на источник;
  - явная публикация;
  - удаление черновика;
  - отключение и повторное включение;
  - восстановление любой сохранённой версии;
  - append-only журнал действий с исполнителем и временем.
- Optimistic locking общей ревизии защищает от перезаписи изменений из другой вкладки.
- Два явных уровня параметров:
  - общее значение для всей товарной серии;
  - значение только для выбранного исполнения.
- В интерфейсе область не выбирается автоматически: администратор обязан подтвердить её вручную, поэтому диаметр одного исполнения не может случайно распространиться на остальные размеры.
- Новая capability `catalog:manage` доступна только администратору.
- API защищён серверной авторизацией, same-origin, лимитом тела и rate limit.
- Опубликованные корректировки применяются поверх фида в:
  - карточке товара;
  - категории и фильтрах;
  - снимке каталога;
  - поиске;
  - отчёте качества и очереди обогащения.
- Кэши поиска, фасетов и отчёта качества обновляются по ревизии корректировок; пакетное применение читает runtime-хранилище один раз на набор товаров.
- Добавлено рабочее место `/test/catalog-parameters` с поиском, фильтрами, подсказками отсутствующих параметров, текущими значениями, черновиком, контролем версии и аудитом.
- Из очереди качества добавлены прямые переходы к категории и конкретному товару для исправления характеристик.
- Desktop использует компактную табличную строку параметра; mobile перестраивает каждую строку в вертикальную форму без горизонтального переполнения.

## Известные ограничения

- Файловое хранилище рассчитано на текущий одноинстансовый тестовый стенд. Перед горизонтальным масштабированием нужен общий datastore, резервное копирование и межпроцессная блокировка.
- Ссылка на источник сохраняется как доказательство, но система не скачивает и не интерпретирует паспорт автоматически.
- Массовый импорт из файла намеренно не добавлен: сначала нужен формат импорта, предпросмотр diff и построчная валидация.
