# Конверсионный поиск каталога

- Исполнитель: Codex.
- Ветка: `codex/smart-search-conversion`.
- База: `cd7ce59` — утверждённая карточка товара, запрос КП и необязательные реквизиты.
- Область: локальный макет `design-exploration/staging-pilot`, интерфейс поиска, поиск по данным фида, zero-results, стили и регрессионные тесты.
- Цель: дать покупателю короткий путь к товару по модели, бренду, категории или производственной задаче без знания артикула.
- Ограничения: не менять production/Beget/DNS/секреты; не отправлять формы или лиды наружу; не выдумывать товары, наличие, характеристики и сроки.
- Критерий готовности: поиск показывает релевантные товары, категории и задачи, поддерживает клавиатуру и мобильный экран, а нулевая выдача ведёт к подбору без потери введённого запроса.

## Результат

- Жёстко заданные подсказки в header/hero заменены единым компонентом поиска по локальному снимку реального товарного фида.
- Поиск ранжирует точные модели и артикулы выше широких совпадений, затем показывает товары, категории и производственные задачи отдельными группами.
- В индекс входят название, бренд, серия, артикулы вариантов, категория и значения характеристик. Русская морфология частично учитывается через совпадение смысловых основ; технические размеры вида `35×30` нормализуются без порчи русской буквы «х» в словах.
- Добавлены debounce, отмена устаревшего запроса, ограничение длины строки, серверный API `/api/catalog-search`, предварительно нормализованный индекс и ограниченный JSON-ответ.
- Добавлена доступная навигация: combobox/listbox, `ArrowUp`/`ArrowDown`, `Escape`, `Enter`, активный вариант через `aria-activedescendant`.
- Создана полная страница `/search?q=...`: реальные фото, цены, честный статус наличия, ключевые характеристики, переход к исполнению и добавление в КП только конкретного варианта.
- При нулевой выдаче нет тупика и нет `mailto`: введённый текст сохраняется и подставляется в локальную форму инженерного подбора; также доступна форма обратного звонка.
- Аналитика поиска не получает текст запроса: передаются только placement, длина запроса, распознанный тип, количество результатов, тип и позиция выбранного результата.
- Существующая карточка товара и запрос КП сохранены без функциональных изменений.
