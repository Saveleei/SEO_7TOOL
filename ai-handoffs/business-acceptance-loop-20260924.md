## Цель

Автоматизировать и доказательно пройти полный B2B-цикл: точное исполнение товара → заявка на КП → сохранение → кабинет менеджера → черновик и согласование КП → PDF → удержанный пакет доставки. Внешние email/MAX/CRM не вызываются, рабочие заявки test-контура не изменяются.

## Критерии готовности

1. Один повторяемый сценарий создаёт синтетическую заявку через публичный API и проверяет номер, контекст товара, вариант, количество, attribution и согласие.
2. Менеджер входит временной однократной учётной записью и видит ту же заявку без потери данных.
3. КП формируется с характеристиками, фотографией при наличии, НДС 22%, реквизитами и PDF.
4. Подготовка доставки заканчивается только локальным outbox/hold; внешний транспорт не вызывается.
5. Сценарий использует отдельный временный каталог данных, сам очищается и не содержит персональных данных.
6. Узкие тесты, полный ESLint, `npm test`, build и изолированный server smoke проходят.

## Ограничения и следующий gate

- Сценарий намеренно не записывает синтетическую заявку в рабочий каталог test и не вызывает внешние email/MAX/CRM.
- Следующая приоритетная приёмка — один пользовательский проход в браузере через внешний reverse proxy с действующей test-учётной записью и синтетическими данными. Он нужен только для проверки реальных кликов/фокуса/мобильной формы; серверная целостность и PDF уже доказаны этим runner.
- После UI-прохода приоритетом остаётся устранение известной beta-ошибки Vinext RSC-prefetch и проверка воронки аналитики.
