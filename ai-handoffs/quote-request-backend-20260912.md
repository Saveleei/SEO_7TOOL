# Тестовый серверный контур запросов КП

- Исполнитель: Codex.
- Ветка: `codex/quote-request-backend`.
- База: `7b41d44` — утверждённый поиск, карточка товара и конверсионный черновик КП.
- Область: локальный макет `design-exploration/staging-pilot`, API запроса КП, серверная валидация, тестовое хранилище, confirmation-state, локальный журнал и регрессионные тесты.
- Цель: заменить клиентскую имитацию надёжным локальным циклом «проверить → сохранить → присвоить номер → показать менеджеру», сохранив внешний маршрут уведомлений отключённым.
- Ограничения: не менять production/Beget/DNS/секреты; не отправлять email, MAX, Telegram, CRM или тестовые лиды наружу; не сохранять файлы и персональные данные вне локального тестового контура.
- Критерий готовности: валидная заявка получает серверный номер только после сохранения, невалидная/спам-заявка отклоняется понятным ответом, повторная отправка защищена, а менеджер видит локальный журнал без раскрытия реквизитов в аналитике.

## Результат

- Клиентская имитация номера заменена POST-запросом на same-origin API `/api/quote-requests`.
- API работает только при явном `QUOTE_TEST_MODE=1`; без флага возвращает 503 и ничего не сохраняет.
- Заявка получает серверный номер вида `7T-YYYYMMDD-XXXXXX` только после append-only записи и `fsync` локального журнала.
- Повторная отправка защищена UUID idempotency key: сервер хранит только SHA-256 hash, повтор использует уже созданный номер.
- На сервере повторно проверяются email, телефон, согласие, состав заявки, количество, длины строк, origin и honeypot; действует in-memory rate limit 8 попыток за 10 минут.
- ИНН проверяется по российскому checksum, а вложение PDF/JPG/PNG — по MIME, размеру до 10 МБ и сигнатуре содержимого.
- Файл карточки организации сохраняется только в локальной игнорируемой папке `work/quote-requests/uploads`; имя генерируется сервером.
- Сохраняются точные позиции, требования и только разрешённые UTM-поля. Полная строка поискового запроса в аналитику не передаётся.
- Добавлен локальный журнал `/test/requests`: контакты маскируются, ИНН и вложение не раскрываются, показаны состав, источник и этапы обработки.
- Внешняя доставка зафиксирована как `disabled-test-contour`; в API/хранилище отсутствуют вызовы email, MAX, Telegram или CRM.
- Confirmation-state прямо сообщает, что запись уже сохранена локально, а внешние каналы отключены.

## Ограничения перед production

- Локальный JSONL и файловая папка подходят только для изолированного тестового контура. Перед production нужно заменить адаптер на транзакционную БД и закрытое объектное хранилище.
- In-memory rate limiter нужно заменить распределённым хранилищем, а журнал — защитить аутентификацией и ролями.
- Подключение email/MAX/CRM выполнять только после утверждения маршрутизации, секретов, retention и политики обработки персональных данных.
