# Quick order conversion

- Исполнитель: Codex
- Ветка: `codex/quick-order-conversion`
- Базовый commit: `1401ca004c62d9786855f1e7b1a2a366fba84403`
- Цель: сократить путь от выбранной позиции до сохранённой заявки, не подменяя многопозиционный сценарий КП и не обещая заказ при неподтверждённых цене или наличии.
- Область файлов: `design-exploration/staging-pilot` — карточки каталога, buybox товара, переиспользуемая форма быстрого запроса, стили, аналитика и тесты.
- Критерии готовности:
  - для конкретного исполнения с подтверждённой ценой и наличием используется формулировка «Быстрый заказ»;
  - для неподтверждённой позиции используется «Быстрый запрос»;
  - форма получает товар, исполнение, количество и контекст страницы автоматически, требует минимум ручного ввода, сохраняет заявку сервером и показывает номер;
  - в карточке категории быстрый сценарий вторичен и не перегружает карточку; для группы вариантов сначала требуется выбрать исполнение;
  - КП остаётся основным сценарием для нескольких позиций;
  - события аналитики не содержат телефона, имени, email или иных персональных данных;
  - desktop/mobile проверены без фактической отправки внешних сообщений.
- Ограничения: production, test.7tool.ru, Beget, cron, DNS и секреты не изменяются; внешние и тестовые заявки не отправляются.
- Проверки: узкие тесты, ESLint изменённых файлов, полный `npm test`, `npm run build`, браузерная проверка desktop/mobile.
- Реализовано:
  - добавлен единый `QuickOrderDialog` для карточек, таблицы категории и buybox товара;
  - подпись определяется по точному исполнению: «Быстрый заказ» только при подтверждённом наличии и фиксированной рублёвой цене, иначе «Быстрый запрос»;
  - короткая форма передаёт точный товар, артикул, количество, UTM и контекст страницы, требует телефон и согласие, сохраняет заявку через существующий защищённый API и показывает номер;
  - в журнал менеджера добавлен отдельный тип `quick_order`; email для него необязателен, телефон и серверные защиты обязательны;
  - аналитика содержит только разрешённый контекст товара и размещения, без контактов клиента;
  - пустое действие «Открыть КП» в buybox скрыто, пока в КП нет позиций.
- Проверки:
  - узкие тесты быстрого заказа и backend: 16/16;
  - полный набор тестов: 306/306;
  - полный ESLint: успешно;
  - production build Vinext: успешно;
  - browser desktop: карточка товара и раскрытые варианты категории проверены;
  - browser mobile 390 × 844: bottom-sheet, прокрутка, поля, согласие и кнопки проверены;
  - заявки при browser-проверке не отправлялись; внешний контур не вызывался.
