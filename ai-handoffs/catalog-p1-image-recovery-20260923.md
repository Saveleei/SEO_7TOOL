# Catalog P1 image recovery — 2026-09-23

- Исполнитель: Codex.
- Ветка: `codex/catalog-p1-image-recovery`.
- База: `affca0a`.
- Коммит реализации: `9db1ab8`.
- Область: 658 P1-задач `missing_image` в витрине нового каталога.

## Цель

Сократить число карточек без фотографии только за счёт доказуемых изображений товара: текущего фида, точного исполнения, той же подтверждённой товарной серии или официального источника производителя/поставщика.

## Ограничения

- Не использовать похожие товары, логотипы, заглушки, изображения конкурентов или генеративную графику как фотографию товара.
- Не присваивать изображение серии, если нельзя доказать, что оно относится ко всем объединённым исполнениям.
- Не менять исходный фид, production, `test.7tool.ru`, Beget или внешние каналы без отдельного решения.
- Сомнительные совпадения оставлять в очереди ручной проверки.

## Критерий готовности

- Все 658 записей классифицированы по причине отсутствия изображения и возможному источнику.
- Автоматически восстановлены только однозначные случаи с проверяемым происхождением.
- Для оставшихся записей сформирована точная очередь без выдуманных медиа.
- Узкие тесты, полный lint, тесты, build и браузерная QA проходят.

## Классификация исходной очереди

В базовом отчёте было 658 товаров без фотографии. Автоматическое сравнение по похожему названию отвергнуто: например, `RobotMeta RM 2000/6 HW PLUS` ошибочно сближался с `RM 2000/6 HW`, хотя это разные исполнения.

Найден безопасный пакет из 21 товарного семейства:

- все позиции существуют в текущем снимке фида;
- имеют положительный остаток;
- по-прежнему не имеют изображения ни у товара, ни у вариантов;
- ранее были вручную сверены с точными страницами K2Tool;
- локальные WebP-файлы имеют зафиксированные размер и SHA-256.

Пакет содержит 20 уникальных файлов общим размером 442 752 байта. Два семейства метчиков ONIX используют один байт-в-байт одинаковый снимок, который поставщик публикует на обеих точных страницах.

## Реализация

- Добавлен неизменяемый реестр `verifiedProductMedia` с точным ID, брендом, артикулом, полным названием, страницей-источником, исходным URL, локальным файлом, размером и SHA-256.
- Обогащение выполняется только при полном совпадении всех полей идентичности и только если фид не содержит собственного изображения.
- Товарные данные не изменяются на месте: витрина получает производный снимок с локальным проверенным фото.
- Поиск переведён с прямого чтения исходного JSON на общий `getPublishedFeedCatalogSnapshot()`. Благодаря этому карточка, категория, поиск, рекомендации и КП используют один источник изображения.
- Остаток очереди получает понятную рабочую подсказку вместо общего текста «нет фотографии».

## Защита от ошибочного фото

- Существующее медиа фида имеет безусловный приоритет и не перезаписывается.
- Изменение бренда, артикула или названия отключает ручное назначение до повторной проверки.
- Каждый локальный файл проверяется по длине и SHA-256 в регрессионном тесте.
- Приблизительное совпадение названий, общий бренд или похожая форма инструмента недостаточны.
