# Production memory headroom — 2026-09-29

- Исполнитель: Codex.
- Ветка: `codex/production-memory-headroom-20260929`.
- Базовый commit: `ef51646`.
- Область: production PM2 memory guard и его регрессионный контракт.

## Причина

Финальный loopback-гейт на объединённом каталоге K2Tool + Stalex прошёл функционально, но после 58 маршрутных проверок и 30 read-only запросов с concurrency 4 процесс занял `995636 KB` RSS. Это ниже прежнего порога `1024M`, но оставляет около 52 MiB и создаёт риск ложного PM2-рестарта при обычном трафике.

## Изменение

- `max_memory_restart` увеличен с `1024M` до `1280M`.
- Порог остаётся ограниченным и оставляет примерно 280–300 MiB запаса относительно измеренного пика.
- Приложение, маршруты, фид, формы, production, DNS, Nginx и активные процессы не меняются.

## Критерий готовности

- узкий production-readiness тест проходит;
- полный набор тестов, ESLint и build проходят либо базовые несвязанные отклонения зафиксированы отдельно;
- новый кандидат, собранный на текущем production-feed SHA, проходит loopback smoke и read-only нагрузку без рестартов;
- production и test процессы сохраняют PID, restart count и cwd.
